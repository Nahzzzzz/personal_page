# 个人主页 PRD

> 版本 v1.0 · 最后更新 2026-10-16 · 状态：本地端到端验证通过，云上部署待执行
> 技术方案见 [TECH_DESIGN.md](./TECH_DESIGN.md)，仓库约定与操作手册见 [../AGENTS.md](../AGENTS.md)。

## 1. 背景与问题

一个技术人的个人主页，内容会不断变：换工作要改职位和经历、接新项目要加卡片、换了邮箱要改联系方式。

纯静态站的做法是把文案写在代码里，每次改动都要「改文件 → 提交 → 重新部署」。这件事的成本不在于难度，而在于**频率**：一年改三十次，就有三十次打断。更麻烦的是，很多改动发生在不方便开电脑的场景里（比如刚下班在地铁上想起要补一个项目链接）。

所以这个项目要解决的核心问题只有一个：**改站点上显示的个人信息，不需要碰代码、不需要重新部署。**

## 2. 目标与非目标

### 目标

| 编号 | 目标 | 衡量方式 |
| --- | --- | --- |
| G1 | 站点主人能在浏览器里修改页面上所有可见文字 | 后台覆盖 11 个分区，页面文字 100% 来自可编辑字段 |
| G2 | 改完内容不需要重新部署，刷新页面即生效 | 内容存 D1，前台每次加载时拉取，带 ETag 协商缓存 |
| G3 | 改错了能退回去 | 每次保存自动留快照，每种语言保留最近 20 份，一键恢复 |
| G4 | 中文和英文各自独立维护 | 两个语言各存一行，切换编辑互不影响 |
| G5 | 零运维、零成本 | 跑在 Cloudflare Pages + D1 免费额度内，无服务器需要维护 |
| G6 | 后台不可用时站点依然完整 | 内容有内置默认值兜底，接口挂了也只是看到旧内容 |

### 非目标（v1 明确不做）

- **文件上传**。简历 PDF、头像这类二进制文件要自己放进 `public/` 再部署。后台只改文字和链接。
- **富文本 / Markdown**。所有字段都是纯文本，段落是「一段一个输入框」的字符串数组。
- **多人协作**。只有一把密码，没有账号体系、没有权限分级、没有操作审计。
- **草稿与预览**。保存即生效，没有「先存草稿再发布」的两段式流程。
- **中英之外的语言**。语言列表硬编码为 `zh` / `en`。
- **评论、访问统计、联系表单**。页面是纯展示 + `mailto:`，没有任何后端写入入口对外开放。
- **通用 CMS**。字段定义写死在 `public/assets/admin/schema.js`，不做「想加什么字段就加什么字段」。

## 3. 用户与场景

| 角色 | 描述 | 关心什么 |
| --- | --- | --- |
| 站点主人（唯一编辑者） | 有技术背景，但不想为了改一句话去开编辑器 | 改得快、改不错、能撤回 |
| 访客：招聘方 / HR | 从简历或社交平台点进来，通常只停留几十秒 | 姓名、职位、经历、怎么联系 |
| 访客：同行 / 潜在合作方 | 会看项目和技术栈，可能会看英文版 | 项目做了什么、技术选型、英文是否通顺 |
| 爬虫 | 搜索引擎和社交平台的抓取 | 结构化数据、`og:` 标签、`lang` 是否正确 |

### 用户故事

| 编号 | 故事 | 验收方式 |
| --- | --- | --- |
| US-1 | 作为主人，我在 `/admin` 改一句自我介绍并保存，刷新站点就能看到新内容 | 保存后 `GET /api/content` 返回新值，页面重绘 |
| US-2 | 作为主人，我改错了想退回上一版 | 「修改历史」里点「恢复」，内容回到那一版，且这次恢复本身也记一条历史 |
| US-3 | 作为主人，我想只改英文版，中文保持不变 | 语言标签各自保存，另一种语言的内容不受影响 |
| US-4 | 作为主人，我想把整份内容备份下来 | 「导出全部内容」下载 JSON，「从文件导入」整体覆盖 |
| US-5 | 作为主人，我想清掉后台所有改动，回到代码里的默认内容 | 「恢复当前语言默认」，且当前版本会留在历史里 |
| US-6 | 作为访客，我点语言按钮能切到英文，下次进来还是英文 | 选择记在 `localStorage`，首次进入按浏览器语言判断 |
| US-7 | 作为访客，当后台接口挂了或我离线，页面依然完整可读 | 内置默认值先渲染，接口失败时用 `localStorage` 缓存或默认值 |
| US-8 | 作为主人，我担心后台被人乱改 | 未登录的写操作一律 401；后台和接口都不被搜索引擎收录 |

## 4. 功能需求

### FR-1 前台展示（P0）

单页滚动，固定导航 + 锚点跳转 + 滚动高亮当前区块。区块顺序：

| 区块 | 内容 | 数据来源 |
| --- | --- | --- |
| 导航栏 | 站点标识、菜单项、语言切换、移动端汉堡菜单 | `nav.*` |
| 首屏 | 状态标签、姓名、职位、一句话简介、两个按钮、社交图标组 | `hero.*`、`links.*`、`terminal.*` |
| 关于我 | 小标题、标题、导语、正文段落、事实清单 | `about.*` |
| 技能 | 导语、分组（组名 + 技能标签） | `skills.*` |
| 项目 | 导语、卡片（名称、说明、技术栈、演示/源码链接） | `projects.*` |
| 工作经历 | 导语、时间线（时间、职位、公司、要点列表） | `experience.*` |
| 联系 | 导语、邮箱按钮、社交图标组 | `contact.*`、`links.*` |
| 页脚 | 署名、技术说明、回到顶部、年份 | `footer.*` |

细节要求：

- 项目卡片的缩略图是 CSS 渐变，6 套配色按顺序循环，不依赖任何图片资源。
- 卡片上的演示/源码链接**留空就不渲染**，避免出现指向 `#` 的死链。
- 「下载简历」的文件名为空时，按钮隐藏而不是留着死链。

### FR-2 双语（P0）

- 中文为默认语言，`<html lang>` 和 `og:locale` 随语言切换。
- 首次进入按 `navigator.languages` 判断，之后记在 `localStorage`（键 `site:locale`）。
- 页面文字通过 `data-i18n` / `data-i18n-<attr>` 标记识别，不在 JS 里写死文案。
- 结构化数据（`application/ld+json`）随当前语言刷新。

### FR-3 内容后台（P0）

入口 `/admin`，密码登录，登录态是一枚签名 Cookie（有效期 7 天）。

| 能力 | 说明 |
| --- | --- |
| 分区编辑 | 左侧 11 个分区，右侧表单由字段定义生成，顶部切换中/英 |
| 脏标记 | 改过的字段高亮，侧边栏显示该分区改动条数，保存按钮显示总条数 |
| 补丁保存 | 只发改动过的字段，服务端深合并；`Ctrl / Cmd + S` 同效 |
| 离开前拦截 | 有未保存改动时，刷新或关闭页面会弹确认 |
| 输入类型 | 单行文本、多行文本、URL（浏览器校验）、字符串列表、对象卡片列表 |
| 列表操作 | 增、删、上移、下移；删除前二次确认 |
| 恢复默认 | 丢弃该语言的后台内容，回到代码里的默认值（当前版本进历史） |
| 导入导出 | 导出全部内容为 JSON；导入时整体覆盖，并告知覆盖哪些语言 |

### FR-4 历史版本（P1）

- 每次保存（含「恢复默认」和恢复历史）都自动留一份快照。
- 每种语言保留最近 20 份，超出自动清理。
- 列表显示时间和体积，可一键恢复；恢复本身也是一次正常写入。

### FR-5 部署与配置（P0）

- 部署目标 Cloudflare Pages，静态资源 + Functions + D1 一套配置搞定。
- 密码和签名密钥通过 Cloudflare 密钥注入，不落在仓库里。
- 首次部署后需要在后台把「站点地址」改成正式域名（影响 `og:url` 和结构化数据）。

### FR-6 降级与容错（P0）

| 故障 | 表现 |
| --- | --- |
| 接口未部署 / 网络不通 | 用内置默认值渲染，控制台留一条 info，页面完整 |
| D1 未绑定或 `database_id` 没填 | 读接口返回 503 并说明原因；页面仍然完整（走默认值） |
| D1 里的内容不是合法 JSON | 忽略这一行数据，退回默认值，服务端日志留痕 |
| 后台内容把某个区块的类型写坏 | 前台忽略这次覆盖，服务端在写入前就会拦下 |
| 未登录或登录过期 | 写接口 401，后台自动回到登录页并提示 |

## 5. 非功能需求

### 性能

- 静态资源零构建、零依赖、零第三方请求（无字体 CDN、无分析脚本、无图片）。
- 首屏不阻塞：内置内容同步渲染，后台内容取到后再整体重绘一次。
- 读接口用 ETag 协商缓存，内容没变时返回 304，不重传整份内容。

### 安全

| 项 | 做法 |
| --- | --- |
| 密码存储 | 只存在 Cloudflare 密钥里，代码和数据库都没有 |
| 密码比较 | 双方先各自摘要再等长比较，避免耗时差泄漏信息 |
| 会话 | `HttpOnly` + `SameSite=Strict` + https 下加 `Secure`，内容只有过期时间和 HMAC 签名 |
| 暴力尝试 | 同一 IP 10 分钟内失败 8 次后拒绝，并给失败请求加 400ms 延迟 |
| 内容注入 | 页面所有来自后台的文字都用 `createElement` + `textContent` 构建，不用 `innerHTML` |
| 原型污染 | 写入前拒绝 `__proto__` / `constructor` / `prototype` 字段名 |
| 体积 | 单次请求体上限 256KB，单语言内容上限 200KB |
| 收录 | 后台页面 `noindex`，`robots.txt` 屏蔽 `/admin`、`/api`，接口响应带 `X-Robots-Tag: noindex` |
| 点击劫持 | `X-Frame-Options: DENY` |

### 可访问性

语义标签、键盘可用的跳转正文链接、焦点描边、`aria-current` 标记当前区块、`aria-expanded` 标记菜单状态、读屏专用的提示文字（`links.*Label`、`nav.label`、`terminal.label`）、尊重系统「减少动态效果」设置。

### 兼容与响应式

- 前台 900px 以下切换为汉堡菜单，字号和间距用 `clamp()` 流体缩放，560px 以下再收紧导航高度。
- 后台 1080px 以下收窄侧边栏，760px 以下变成单列，手机上可以改内容。
- 只用系统字体栈，不下载字体文件。

### 成本

Cloudflare Pages 免费版 + D1 免费额度（每天 500 万次读取、10 万次写入）。按个人主页的访问量，正常使用不会产生费用。

## 6. 验收清单

上线前逐条确认：

- [ ] 未登录访问 `GET /api/session` 返回 `{"authenticated":false,...,"configured":true}`
- [ ] 未登录 `PUT /api/content`、`POST /api/revisions`、`GET /api/revisions` 全部 401
- [ ] 错误密码连续 8 次后被限流（429）
- [ ] 登录后改一个字段并保存，刷新站点能看到；`GET /api/content` 里只有改过的字段
- [ ] 保存后编辑器里没改过的字段仍是原值（不是空白）
- [ ] 中英文分别保存，互不干扰
- [ ] 把一个对象字段换成字符串会被拒绝（400，错误信息里带字段路径）
- [ ] `__proto__` 补丁被拒绝，且全局 `Object` 未被污染
- [ ] 保存次数超过 20 次后，历史列表仍只有 20 条
- [ ] 「恢复」能把内容退回指定版本；「恢复默认」能回到内置内容
- [ ] 导出 JSON 再导入，内容一致
- [ ] 「站点地址」已改成正式域名
- [ ] 简历 PDF 已放进 `public/`（或已清空文件名让按钮隐藏）
- [ ] 断网或停掉后台接口后，站点依然完整显示
- [ ] 移动端（<900px）菜单可用，后台（<760px）可编辑

## 8. 风险与依赖

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 登录限流只作用于单个 isolate | 分布式暴力尝试可能绕过 | 目前接受；需要更严时给 `/admin` 与 `/api/*` 加 Cloudflare Access 或 Rate Limiting 规则 |
| 只有一把密码 | 无法区分谁改的，也无法单独撤销某个人的权限 | 目前接受；换密码需要同时更新 Cloudflare 密钥 |
| 内容只存 D1 一份 | 误删数据库会丢掉后台内容（内置默认值仍在代码里） | 定期「导出全部内容」留一份 JSON |
| 简历 PDF 不在后台管理范围 | 改简历要重新部署 | 明确为非目标；文件名可在后台改，文件本身手动替换 |
| 首屏语言闪烁 | 英文用户首次进入会先看到一瞬间中文 | 已知取舍，换取「不依赖 JS 也能看到完整内容」 |
| 依赖 Cloudflare | 迁移到别的平台要重写 Functions | 前台是完全静态的，迁移成本主要在 `functions/` 这一层 |

## 9. 后续可能的方向

按价值排序，暂时都不在 v1 范围：

1. **图片与附件上传**（简历 PDF、头像）——需要引入 R2 或 KV 存储 + 上传接口 + 前端裁剪预览。
2. **草稿与预览**——保存到独立字段，站点只在「发布」后读生效版本。
3. **Cloudflare Access 保护后台**——比单一密码更强的身份验证，且能记录访问者。
4. **内容体积与访问量统计**——纯前端可做，但和个人主页的定位不太匹配。
5. **更多语言**——语言列表硬编码在两处，抽成配置后可以扩展。
